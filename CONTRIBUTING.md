## How to contribute to respond

#### **Did you find a bug?**

* **Ensure the bug was not already reported** by searching on GitHub under [Issues](https://github.com/SyndemicsLab/respond/issues).

* If you're unable to find an open issue addressing the problem, [open a new one](https://github.com/SyndemicsLab/respond/issues/new). Be sure to include a **title and clear description**, as much relevant information as possible, and a **code sample** or an **executable test case** demonstrating the expected behavior that is not occurring.

* If possible, use the relevant bug report templates to create the issue. 

#### **Did you write a patch that fixes a bug?**

* Open a new GitHub pull request with the patch.

* Ensure the PR description clearly describes the problem and solution. Include the relevant issue number if applicable.

#### **Did you fix whitespace, format code, or make a purely cosmetic patch?**

Changes that are cosmetic in nature and do not add anything substantial to the stability, functionality, or testability of respond will generally not be accepted ([we concur with Ruby on Rails rationales behind this decision](https://github.com/rails/rails/pull/13771#issuecomment-32746700)).

#### **Do you have questions about the source code?**

* Ask any question about how to use respond in the [discussion board](https://github.com/SyndemicsLab/respond/discussions).

#### **Do you want to contribute to respond documentation?**

* Please ensure that all documentation changes are compatible with previous versions of respond as well. They will go through testing with internal Syndemics Lab members.

respond is made by the Syndemics Lab for the greater substance use disorder research community. We encourage you to pitch in and join the team!
